# Google Play 公開チェックリスト

HonTalk を Google Play に公開するための手順とメタデータ下書きです。
App Store 審査待ちの間に、ここまで進めておけます。

> **App Store との最大の違い**
> 個人デベロッパーアカウント（2023年11月13日以降に作成）では、
> **クローズドテスト（テスター12人以上が14日連続でオプトイン）** を終えてから
> 本番公開を申請します。いきなり本番トラックには出せません。

---

## 全体の流れ

```
1. Play Console アカウント作成（未作成なら $25）
2. アプリを作成し、ストア掲載情報を埋める
3. 本番 AAB をビルドしてクローズドテストにアップロード
4. テスター12人以上を招待し、14日間待つ
5. 本番公開を申請 → 審査 → 公開
```

内部テスト（最大100人）は任意です。**12人×14日の条件にカウントされるのはクローズドテストだけ**です。

---

## Step 1: Google Play Console アカウント

1. [Google Play Console](https://play.google.com/console/signup) でデベロッパー登録
2. 初回登録料 **$25（一度きり）**
3. 本人確認（身分証明書）が求められることがあります。承認まで数日かかることがあります

すでにアカウントがある場合は、このステップは不要です。

## Step 4: 本番 AAB をビルドする

Google Play は新規アプリに **AAB（Android App Bundle）** を要求します。
`eas.json` の `production` プロファイルは AAB を出力します（`development` / `preview` は APK なので提出不可）。

```bash
npx eas build --profile production --platform android
```

初回は EAS が Android 用アップロードキーを発行します。キーストアは EAS に保管されます。紛失しないよう、後で `eas credentials` からバックアップしてください。

---

## Step 5: Play Console にアップロードする

### 方法 A: Play Console から手動（初回におすすめ）

1. EAS ビルド完了後、AAB をダウンロード
2. Play Console → **テスト** → **クローズドテスト** → リリースを作成
3. AAB をアップロード

### 方法 B: EAS Submit（2回目以降が楽）

先に Google Cloud のサービスアカウントを作り、Play Console API 権限を付けて JSON キーを EAS に登録します。

```bash
npx eas credentials --platform android
# production → Google Service Account → Upload a Google Service Account Key

npx eas submit --platform android
```

> `google-services.json`（Firebase / プッシュ通知用）と、
> Play Console API 用のサービスアカウント JSON は **別物** です。混同しないでください。

初回提出後、リリースは Play Console 側で「審査に送信」します。

## Step 6: クローズドテスト（本番公開の前提）

1. **テスト** → **クローズドテスト** でテストを作成（名前例: `closed-launch`）
2. テスターをメールアドレスで追加するか、Google グループを使う
3. **オプトイン URL** をテスターに共有する
4. テスターはリンクを開き、**テスターになる** を押してから Play ストアでインストールする

条件（個人アカウント / 2023-11-13 以降作成）:

- **12人以上** がオプトインした状態を維持
- それが **14日連続** 続く
- 招待しただけではカウントされない。必ず「テスターになる」を押してもらう
- 途中で12人を下回ると日数がリセットされることがあるので、余裕を見て **15人以上** 招待する

14日経過後、ダッシュボードの **本番へのアクセスを申請** から質問に回答します。
知人・読書コミュニティへの案内方法、もらったフィードバック、直した点を具体的に書くと通りやすいです。

組織アカウント、または 2023-11-13 より前の個人アカウントは、この待ちをスキップできることがあります。Play Console の表示が正です。

## Step 7: Android 固有の技術確認

### ログイン

- メール + パスワード: Android でもそのまま使える
- Google ログイン: Supabase OAuth + アプリ内ブラウザ。追加の SHA-1 設定は不要
- Apple ログイン: **iOS のみ**（Android では出さない）

審査用アカウントは App Store と同じものを使えます。

### プッシュ通知（FCM）

Android 本番で通知を送るには Firebase の `google-services.json` が必要です。
未設定でもストア提出自体はできますが、**Android では通知が届きません**。

後で入れる手順:

1. [Firebase Console](https://console.firebase.google.com/) でプロジェクト作成
2. Android アプリを追加（パッケージ名 `com.hontalk.app`）
3. `google-services.json` をダウンロード
4. Expo のドキュメントに従い EAS に FCM V1 キーを登録
   https://docs.expo.dev/push-notifications/fcm-credentials/

クローズドテスト開始前に入れておくと、テスターに通知も確認してもらえます。

### 権限

カメラは ISBN スキャンに使います。マイクは使いません。
`RECORD_AUDIO` は提出前に外してあります。

## 審査で見られやすい点（HonTalk）

- ログイン必須アプリは **審査用アカウント** を Play Console の「アプリ コンテンツ」に書く
- UGC（レビュー・コメント）があるので、通報・ブロック・ミュートの場所を説明に書く
- プライバシーポリシー・サポートページが開けること
- 使っていない権限（特にマイク・位置情報）を宣言しない

審査用メモ（下書き）:

```
テスト用アカウント:
メール: [審査用メールアドレス]
パスワード: [8文字以上]

ログイン方法: メール+パスワード、Google ログインに対応しています。
Apple ログインは iOS のみです。

主要機能はログイン後、タイムライン・書籍検索・レビュー投稿・本棚・ランキングから確認できます。
不適切な投稿は、レビューまたはプロフィールから通報できます。
ブロック・ミュートは設定画面から確認できます。
```
